Motivation
在去中心化交易所中，API 和 Subgraph 服务可能会失败，导致用户无法进行交易。PancakeSwap 需要一个可靠的降级机制，确保在外部服务不可用时，用户仍然能够直接从区块链获取数据进行交换。这个机制解决了单点故障问题，提高了系统的可靠性和用户体验。

Details
withFallback 函数是降级机制的核心工具 [1a]。它接受一个异步调用数组，按顺序尝试每个选项直到成功。每个选项都可以配置超时时间 [1b]，最后一个选项不设置超时以确保最终执行 [1c]。

降级流程如下：

尝试第一个选项（通常是 API 调用）
如果失败或超时，自动切换到下一个选项
继续尝试直到所有选项耗尽或有一个成功
关键特性：

自动超时处理：防止长时间等待无响应的服务
优雅降级：从 API/Subgraph 降级到纯链上查询
错误隔离：每个选项的失败不会影响其他选项的尝试
最终保证：最后一个选项总是会被执行，确保至少有一种方式获取数据
这个工具函数被整个系统广泛使用，特别是在池子查询和报价获取中，确保即使在网络问题或服务故障的情况下，交换功能仍然可用。
